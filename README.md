把视频里有价值的部分留下来：**Jev 逐段判断字幕或文字稿，代码剪出两个视频——3 分钟的高亮，和只删废话的去水完整版——总结里每一句都能点回原视频的时间点。**

寒暄、广告、空话、鸡汤、夸大其词的段落被过滤掉，每一段舍弃都写明原因；留下来的按价值排序、按原顺序拼成高亮视频。
去水完整版从整片出发，只删确定没用的段，宁可留一点水也不漏信息。
零运行时依赖，Python 标准库跑完全程；剪视频要用 ffmpeg。

```bash
export TYPESAFE_API_KEY=...
jevclip run 视频目录/                               # 整个目录批量跑
jevclip run 访谈.mp4 --focus "硬件配置和运行速度"    # 只要和你关心的内容相关的段
jevclip run 文字稿.md                               # 只有文字稿也行：出取舍和总结
```

## 安装

```bash
cd jevclip
uv tool install --editable .                  # 装成全局命令，任意目录直接敲 jevclip；改了代码不用重装
# 不用 uv：python -m venv .venv && .venv/bin/pip install -e .，命令在 .venv/bin/jevclip
brew install ffmpeg                           # 只看时间线和总结可以不装（加 --no-cut）
echo 'export TYPESAFE_API_KEY=你的key' >> ~/.zshrc   # 然后新开一个终端
```

需要 Python ≥ 3.10、一个 [TypeSafe](https://docs.typesafe.ai) 的 API Key。写总结还需要一个 OpenAI 兼容的模型接口（见[配置](#配置)），没有也能跑，只是总结换成原文摘录。
卸载：`uv tool uninstall jevclip`。

## 准备输入

**转写不在这里做。** 把字幕或文字稿和视频同名放在一起就行：

```text
视频目录/
  第一期.mp4   第一期.srt          # 同名
  第二期.mov   第二期.zh-CN.vtt    # 带语言标签也认
  第三期.mp4   第三期.json         # whisper.cpp 的 -oj 输出
  第四期.mp4   第四期.txt          # 文字稿也行，见下
  第五期.srt                       # 只有字幕：出时间线和总结，不剪视频
```

支持 SRT、WebVTT、whisper.cpp JSON、`[{start, end, text}]` 形式的 JSON。whisper.cpp、faster-whisper、剪映导出的字幕都可以直接用。
找不到字幕的视频会被列出来跳过，不会猜。

### 文字稿（.txt / .md）

直接给文件就行：`jevclip run 文字稿.md`，或者和视频同名放在一起。分两种情况：

| 文字稿 | 怎么处理 | 能剪高亮吗 |
|---|---|---|
| **带时间点**：YouTube「显示文字稿」复制下来的（一行时间一行字）、`[00:01:23] …`、`00:01 - …` | 当字幕用。只有开始时间的，每句的结束按字数估，说话人停顿仍然看得出来 | 能 |
| **没有时间点**：自己的写作底稿、公众号原文 | 按段落和句子切段；Markdown 的标题、列表项、引用各自成句 | 不能——时间不去估算伪造 |

没有时间点的稿子照样出取舍、总结和摘录，位置用原稿的段落编号表示：`[¶7–8]` 是第 7 到第 8 段（空行分段；整篇没有空行时每行算一段）。
单独放在目录里的 .txt / .md 不会被当成文字稿——它可能是任何笔记——要用就直接写它的路径。
改了扩展名的字幕（内容里有 `-->`）照字幕读。

## 输出

每个视频一个文件夹 `jevclip-out/<视频名-短哈希>/`：

| 文件 | 内容 |
|---|---|
| `report.md` | 总结（每条带时间点，覆盖全部有价值片段）、原文摘录、逐段时间线（取舍理由、是否进了高亮）、两个视频的对照表 |
| `highlights.mp4` | 高亮视频，默认不超过 180 秒，只收整段 |
| `full.mp4` | 去水完整版：原片只删掉确定没用的段；一段都不用删时不出这个文件 |
| `highlights.srt` / `full.srt` | 按剪好的视频重新对齐的字幕 |
| `segments.json` | 每段的类型、各项概率、价值分、取舍和理由 |
| `highlights.json` / `full.json` | 每个片段在原视频和剪好的视频里的位置 |

时间线长这样：

| 片段 | 时间 | 类型 | 价值 | 取舍 |
|---|---|---|---|---|
| S1 | 00:00–00:47 | 寒暄过渡 | 0.00 | ✗ 寒暄过渡 1.00；信息密度 0.0/3 |
| S2 | 00:48–01:35 | 推广求关注 | 0.04 | ✗ 推广求关注 0.91；可疑说法 0.99；信息密度 1.3/3 |
| S3 | 01:36–02:25 | 数据实测 | 0.99 | ✓ 保留 |

## 它判断什么

字幕按停顿切成约 20 秒一段：不会拆开任何一条字幕，话说到一半就等下一个停顿再切。段太长会把几件事混在一起打一个平均分（见[实测](#实测)）。每一段 Jev 回答五个问题，都是只针对这一段的绝对判断：

| 问题 | 类型 | 过滤掉什么 |
|---|---|---|
| 这段主要属于哪一类 | 8 选 1：观点结论 / 数据实测 / 方法步骤 / 概念讲解 / 经历叙述 / 寒暄过渡 / 推广求关注 / 空话废话 | 寒暄、广告和求关注、空话 |
| 信息密度和认知价值几分 | 0–3 分：没有信息 / 泛泛而谈（常识、鸡汤、正确的废话）/ 有具体内容 / 高密度 | 低价值、低认知 |
| 有没有夸大、绝对化、缺乏依据的说法 | 是 / 否的概率 | 可疑说法（"全网最强""百分之百"） |
| 脱离前文能不能看懂 | 是 / 否的概率 | 不过滤，用来给高亮排序：能独立看懂的优先 |
| 和你的关注点是否直接相关（可选，最多 5 个） | 是 / 否的概率 | 和每个关注点都无关的段 |

然后由代码决定取舍：

```text
价值 = 信息密度/3 × (1 − 属于寒暄/广告/空话的概率) × 关注点相关度（没设关注点时为 1）
保留 = 价值 ≥ 0.50  且  闲话概率 < 0.50  且  可疑说法 < 0.60  且  关注点相关度 ≥ 0.50
```

高亮视频从保留的段里挑：在时长预算内，让 `价值 × 能否独立看懂 × 时长` 的总和最大（背包算法，前后留白也算进预算），再按原视频顺序拼接。一段如果开头就在接上文——第一句以「而」「第二」「这些」「另一」这类词开头，或 Jev 判它脱离上文看不懂——就必须连同紧挨着的上一段一起入选。相邻入选的段中间停顿不到 2 秒就连着播，不硬切；每段前后各留 0.3 秒，重新编码保证起点帧准。

**去水完整版**反过来，从整片出发，只删确定没用的段：

```text
删掉 = 没被保留  且  （信息密度 < 1.5/3  或  是广告的概率 ≥ 0.80  或  与每个关注点都无关）
```

信息密度不到 1.5 就是 Jev 判为「没有信息」或「泛泛而谈」；广告有具体内容也删。判为寒暄、里面却有具体内容的段——
比如「大家好……9 月 15 日发布，Hacker News 拿到 1679 分」——高亮和总结不收，完整版也不删，报告里单独列出来。
未判断的段、没有字幕的画面（无旁白的演示、片头片尾）都保留；删点两边不到 2 秒的停顿一起删，更长的空白可能是画面演示，留着。
一段都不用删时不出 `full.mp4`，它就是原片；想要"只看有价值的段"的长版本，用 `--max-seconds 0`。

## 谁负责什么

```text
字幕文件 ──► 代码：切段、绑定时间点          Jev 看不到时间戳、文件名和其他段
          ──► Jev：逐段回答五个问题          只给概率，不写一个字
          ──► 代码：按门槛取舍、剪辑、对齐字幕  每个"弃"都有理由；改门槛不再调用 Jev
          ──► 总结模型：只读保留的段          引用片段编号，由代码换成时间点
```

总结模型只能引用 `[S3]` 这样的编号，程序再把编号换成 `[01:36–02:25]`。它引用了不存在或已被舍弃的编号，会被删掉并在报告里注明——编出来的引用变不成时间点。

**总结不遗漏。** 每个有价值片段都必须被至少一条要点引用：程序逐个核对，第一遍漏掉的片段单独交给总结模型再补写一轮，补出的要点按视频顺序插回去；报告里写明「总结引用了全部 N 个有价值片段」，或者列出仍然缺的是哪几段。

总结里的数字（两位以上或带小数）和英文名称，程序会逐行核对：在这一行引用的片段、以及前后各一段里都找不到的，行末标 ⚠。这是为了抓「把 GPT-5.6 Terra 写成 GPT-4o」这类改写——总结模型会把陌生的型号换成自己熟悉的，引用的时间点却是对的。

## 命令

```bash
jevclip run PATH...            # 视频、字幕文件或目录，可以混着给
  --focus TEXT                 # 关注点，可重复，最多 5 个
  --max-seconds 180            # 高亮时长预算；0 = 所有有价值的段都进高亮
  --no-full                    # 不出去水完整版（批量跑时省掉大部分剪辑时间）
  --threshold 0.5              # 价值门槛（临时值，见下）
  --segment-seconds 20         # 目标段长
  --out jevclip-out            # 输出目录
  --subs FILE --title TEXT     # 单个视频时指定字幕 / 标题
  --no-cut                     # 只出时间线和总结
  --no-summary                 # 不调用总结模型
  --fast                       # macOS 硬件编码（VideoToolbox）：文件更大，Apple 芯片上只在 1080p 以上略快
  --no-reuse                   # 忽略缓存，强制重新判断

jevclip export segs.jsonl      # 导出已判断的段，等你标注
jevclip eval segs.jsonl        # 读回标注，推荐门槛
```

**判断一次，门槛随便调。** 每个请求按完整内容（模型、字幕原文、题目措辞）做哈希缓存，存在 `~/.jevclip/cache.db`。
重跑、改门槛、换预算都不再调用 Jev；只有换关注点、改题目或字幕变了才会重新判断。调用失败的段标为"未判断"，
不会被当成没价值，也不进高亮，下次运行自动重试。

## 门槛怎么定

默认门槛是拍出来的临时值。你的视频里什么算"有价值"，要用你自己的标注来定：

```bash
jevclip run 视频目录/                 # 先正常跑一批
jevclip export segs.jsonl             # 每行带原文、时间、当前判断和一个空的 "label"
#   把 "label": null 改成 "keep" 或 "drop"，标 50 段左右，保留和舍弃的都要有
jevclip eval segs.jsonl --max-error 0.1
```

`eval` 会列出每个门槛下：保留下来的段里有多少是你会删掉的（error），你想要的段留下了多少（recall），
并推荐满足 `--max-error` 的最小门槛。把它填进 `--threshold`。导出只包含字幕没变过的段，你标注时读到的就是 Jev 当时读到的字。

## 实测

`examples/` 里有一个**合成**测试：9 分 22 秒、12 段仿写的中文博主口播（寒暄、夸大宣传、实测数据、广告、操作步骤、空话、
概念讲解、鸡汤、带理由的判断、闲聊、纠正误区、结尾），每段预先标好该不该留；视频每段一种纯色，方便逐帧核对高亮剪得对不对。

```bash
python examples/make_demo.py demo
jevclip run demo/
python examples/score_demo.py demo jevclip-out
```

一次运行的结果（jev-1.13.0，2026-09，默认 20 秒段长）：

- 按秒算，12 个块全部判对：该留的块 100% 留下，该删的块 100% 删掉。夸大宣传那段"可疑说法"0.99；鸡汤被判为空话。
- 加关注点"硬件配置和运行速度"后只剩硬件实测、"内存大小不决定速度"两段（这一条是 45 秒段长时测的）。
- 高亮视频逐帧核对，拼进去的正是被选中的三段；总结每条带时间点，没有被标 ⚠ 的行。
- 去水完整版 4:10：该留的 5 块完整保留，该删的 7 块（寒暄、夸大、广告、空话、鸡汤、闲聊、结尾）全部删掉——它们的信息密度都在 1.3 以下。
- Jev 12 次请求、约 1.7 万输入 token、$0.0007。

打分脚本按秒算，而不是按"每段归到哪个块"：之前一版按段中点归块，报的是 12/12，其实纠错那一块的最后一句
被切进了结尾段、跟着"点赞关注"一起删掉，只留下了 88%。

**真实视频**（一期 16 分 52 秒的中文技术讲解，人工字幕，几乎没有寒暄广告）：

| | 每段 45 秒（旧默认） | 每段 20 秒（现默认） |
|---|---|---|
| 开场问候 + "今天来分享一下" | 和背景介绍混在一段，保留 | 单独成段，判为寒暄，舍弃 |
| DOOM 演示（全片最直观的一段） | 和"API 在排队""本期目录"混在一段，平均 0.49，**被舍弃** | 单独成段，保留 |
| "API 在排队""本期目录" | 同上 | 判为寒暄，舍弃 |
| 高亮 | 2 段 2:24，两段都从"第三…"开始，预算剩 36 秒 | 4 段 2:59，从"官方给到的数字…"这类完整开头开始 |
| Jev 请求 / 费用 | 18 次 / $0.0012 | 32 次 / $0.0019 |

同一期视频的第一版总结把"和 GPT-5.6 Terra 的 67.9% 持平"写成了"与 GPT-4o 持平"，这是加总结核对的原因。
核对只看数字和英文名称；意思被悄悄泛化——比如把演示里"每秒约 10 次决策"写成模型的普遍特性——它查不出来。

**有没有遗漏**：按原文整理出这期的 28 个要点（各带起止时间），逐个对照——

| | 覆盖的要点 |
|---|---|
| Jev 判为有价值 | 28/28 |
| 总结（以前限 3–8 条） | 17/28：整段 Skill、"什么时候用/不用"、"LLM 生成、Jev 校验"都没提 |
| 总结（现在：每个有价值片段都要被引用，漏的补写） | 28/28，26 条要点 |
| 3 分钟高亮 | 7/28——3 分钟装不下 28 个要点；时间线的"高亮"一列标出哪些进了、哪些没进 |
| 去水完整版 | 这期一段都不用删，所以没出 `full.mp4`：它就是原片，28/28 |

去水完整版起初的规则是「没进总结的段都删」，这期会剪成 15:44，28 个要点都在。但逐段看被删的两段，
开场那段在「大家好」之后讲了发布日期、Hacker News 1679 分 400 多条评论、第二天 Vercel 宣布接入；
「API 在排队」那段说官方 API 还在排队、可以先走 Vercel AI Gateway。除了最后这条（7:10 又讲了一遍），
这些全片只在这两段里出现过——上面那 28 个参考要点是从 0:35 开始整理的，本身就漏了它们。两段的信息密度都是 2.0/3，
和保留下来的段（最低 2.02）不相上下，只是寒暄概率 0.57、0.74 过了线。所以完整版改成只删确定没用的段；
这两段现在列在报告的「去水完整版」一节里。

剪辑用 ffmpeg 的 libx264（veryfast，CRF 20）重新编码，每段起点帧准。M5 上单独编码一分钟素材：

| 分辨率 | 编码速度 | 输出大小 |
|---|---|---|
| 720p60 | 约 21 倍速 | 2.9 MB/分钟 |
| 1080p30 | 约 7.6 倍速 | 3.7 MB/分钟 |
| 4K30 | 约 1.7 倍速 | 7.6 MB/分钟 |

整段也对得上：这期 720p 视频剪一个 15:45 的完整版，重新编码用了 46 秒；机器同时在跑别的重活（负载 40 以上）时慢到三分多钟。
VideoToolbox 硬件编码（`--fast`）在 1080p 快约 15%、4K 快约 30%，720p 反而更慢；它跟着源视频的码率编码，
文件是默认方式的 3–7 倍，所以不是默认。总结和剪辑同时进行，写总结的时间不再单独算。

**同一期内容做成文字稿**：

- 按 YouTube「显示文字稿」的格式（一行时间一行字，只有开始时间、精确到秒）配原视频跑：切成 27 段（用字幕文件是 32 段，
  因为停顿只能估），开场问候和"API 在排队、本期目录"仍被判为寒暄删掉，照样剪出 4 段、2:57 的高亮。
- 去掉时间、按停顿分段落补上标点，当成写作底稿跑：30 段，开场问候（¶1–2）和本期目录（¶6）被删掉，总结引用显示为 `[¶7–8]`。
  这次暴露一个问题：讲"官方给到的数字"那段被判"可疑说法"0.60，正好压线被删——它在转述官方宣传，质疑在下一段，
  Jev 一次只看一段。"可疑说法"目前分不清"转述官方说法"和"自己夸大"。

以上都是单次运行、一个网络、一个时段的测量，合成样本不代表真实视频上的准确率。按这两次折算，每分钟视频约 1,800–2,600 个
输入 token，100 个 30 分钟的视频约 $0.2–0.3。剪辑是批量跑时最花时间的一步：去水完整版要把大半个视频重新编码一遍，
按上表，1080p 的 30 分钟视频约 4 分钟；不需要时加 `--no-full`。

## 边界

- **"虚假"只能查到一半。** "可疑说法"判断的是这段话有没有说得比它自己给出的依据更满，这是文字本身的性质。
  说法在现实中对不对，Jev 不知道——那需要拿可信资料来对照。
- **只看字幕，看不到画面。** 屏幕演示、PPT 上的信息，口头没说就判断不到。
- **按段取舍。** 一段 20 秒左右，寒暄和干货混在一段时，高亮和总结不收它，去水完整版也不删它——报告里单独列出，需要的话回原片看。
- **转写错字会被照字面理解。** 模型名、产品名最容易转错，转写时给一份热词表效果更好。
- **文字稿没有时间点就剪不了高亮。** 位置只能标到原稿的段落；要高亮，得用带时间点的字幕或文字稿。
- **"可疑说法"会误伤转述。** 一段话只是在复述厂商的宣传数字、质疑在下一段时，也可能被判可疑。
- **解说画面的段落，结论在屏幕上。** "我们来看看它选了哪个"之后字幕没说结果，Jev 照样会给不低的分；总结模型被要求不去猜结果。
- **中文效果以你的标注为准。** 官方说明 Jev 以英文为主要训练语言，中文可以用，但效果要在自己的数据上验证。
- **数据会出本机。** 视频文件不上传；字幕文字会发给 TypeSafe，保留段的文字会发给总结模型。

## 配置

| 环境变量 | 作用 |
|---|---|
| `TYPESAFE_API_KEY` | Jev 的 Key（必需） |
| `JEVCLIP_DB` | 缓存数据库位置，默认 `~/.jevclip/cache.db` |
| `JEVCLIP_LLM_BASE_URL` / `JEVCLIP_LLM_API_KEY` / `JEVCLIP_LLM_MODEL` | 总结模型，任何 OpenAI 兼容接口 |
| `MINIMAX_BASE_URL` / `MINIMAX_API_KEY` | 没配上面三个时使用，模型默认 `MiniMax-M2`；只写域名会自动补 `/v1` |
| `HTTPS_PROXY` | 走代理访问 Jev；macOS 系统代理也会被识别 |

## 作为库使用

```python
from jevclip import Store, Policy, process
from jevclip.jev import JevClient
from jevclip.llm import ChatLLM

with Store("~/.jevclip/cache.db") as store:
    result = process(store, JevClient(), "第一期.mp4", "第一期.srt", "jevclip-out",
                     focus=["本地部署"], policy=Policy(threshold=0.6), llm=ChatLLM.from_env())
    print(result["kept"], result["reel"], result["full"])
```
